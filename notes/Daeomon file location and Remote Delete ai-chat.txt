Based on the daemon code and configuration, the server daemon stores backup set information in the following locations:

## Primary Storage Location
- **Base path**: blzbak (default, configurable via `base_path` in the daemon config)

## Directory Structure
Each backup set is stored in its own subdirectory:

```
/blzbak/                      
├── <set_name>/               # One directory per backup set
│   ├── C/                    # Current backup snapshot
│   ├── O/                    # Once-removed (previous) snapshot
│   └── metadata.yaml         # Backup set metadata
└── diffs/                    # Differential backups
    └── <set_name>/
        └── diff_<timestamp>.tar.gz
```

## Configuration
The storage location can be customized in the daemon config file (see daemon.config.example):
- `base_path`: Main directory for backups (default: blzbak)
- `diff_dir`: Directory for diff archives (default: `{base_path}/diffs`)

The daemon lists all backup sets by scanning subdirectories in the base path that contain either a `C/` or `O/` directory (see the `list_sets()` method in storage.py).

Yes, exactly! When running the dockerized daemon, you need to check the **docker-compose.yml** file to see where blzbak is actually located on your host system.

## Volume Mapping

In docker-compose.yml, you'll find:

```yaml
volumes:
  # Backup storage directory - Your ZFS RAID volume
  # Change /mnt/blzbak to match your actual backup storage path
  - /mnt/blzbak:/blzbak
```

The format is `HOST_PATH:CONTAINER_PATH`:
- **Left side** (`/mnt/blzbak`): The **actual location on your server** where backups are stored
- **Right side** (blzbak): The path **inside the Docker container** (this is what the daemon sees)

## Finding Your Backups

To locate backup sets on your server, look in the host path from docker-compose.yml:

```bash
# Check the current volume mapping
docker inspect blzbak-daemon | grep -A 10 Mounts

# Or view docker-compose.yml
cat docker-compose.yml | grep -A 2 volumes
```

The default setup stores backups in **`/mnt/blzbak`** on the host, which the container sees as blzbak.

## Important Note

The daemon.config file must always use blzbak (the container path), not `/mnt/blzbak`, because the daemon runs inside the container and sees the Docker-mounted path.
